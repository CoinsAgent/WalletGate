# PH-003-B2 — SQLite concurrent-login success

- **Status:** DEFERRED; SQLite concurrency remains unresolved.
- **Origin:** PH-003, original B2; T03 and full WG-003-A1 acceptance.
- **Authorization and reason:** The [approved PH-003 amendment](../plans/history/PH-003.md#approved-ph-003-scope-amendment--2026-11-01) narrowed concurrency acceptance to the user-requested MySQL test. Its structured `scope_amendment.deferred` lists “B2 SQLite concurrent-login success; concurrency acceptance is MySQL only.”
- **Missing behavior:** With two independent auth instances sharing SQLite and submitting the same valid signed challenge concurrently, exactly one authentication succeeds. Preserve durable single use; do not substitute process-local locking or weaken successful-login assertions.
- **Evidence:** [PH-003 B2 investigation](../plans/progress/PH-003.md#reproducible-blockers-and-exact-unblock) records historical `[401,401]`, zero sessions and a database-lock error. The final [PH-003 handoff](../plans/progress/PH-003.md#handoff) records separate MySQL success and retained SQLite limitations. Those results are not a fresh SQLite reproduction or certification of other adapters/multiple processes.
- **Coverage:** WG-003 remains PARTIAL. MySQL acceptance does not certify SQLite, Turso or multiple processes; no storage repair or production migration is approved by this record.
- **Reopening condition:** An explicit user request for the SQLite concurrency case, followed by a scoped plan and its normal Yes/No execution gate. Availability of a database or a general `next` request is insufficient.
- **Closure criteria:** Disposable SQLite tests demonstrate one success and one replay denial, one session and no reusable challenge across independent instances; fresh retries, persistent state and affected authentication/OAuth regressions pass. Record exact adapter/runtime versions and tested process boundaries, then review the result.

This consolidates an already excluded scope item without editing the historical plan, completion record or its evidence hashes. It is not a default next-sprint objective.
